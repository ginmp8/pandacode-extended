## Architecture note

### Reviewer modes, strategy and criteria are separate

The native Council remains the only engine. Its optional, task-scoped schema-v1 composition combines three reviewer sources: A = root Architect-selected automatic reviewers, D = selected persistent bots reviewing directly, and N = selected bots coordinating their own child Councils. The mode is derived from those sources; A/D/N all off is invalid.

| Mode | A | D | N | Composition |
| --- | :---: | :---: | :---: | --- |
| M1 Architect | Yes | No | No | Original automatic Council |
| M2 Bots | No | Yes | No | #126 selected direct reviewers |
| M3 Bots + Architect | Yes | Yes | No | Direct bots plus automatic root seats |
| M4 Bots with own Architect | No | No | Yes | Nested child Council per selected bot |
| M5 Bots with own Architect + Architect | Yes | No | Yes | Child Councils plus automatic root seats |
| M6 Mixed bots | No | Yes | Yes | Direct and nested selected bots |
| M7 Mixed bots + Architect | Yes | Yes | Yes | All three sources |

Each selected bot is assigned to one branch once. An executing bot cannot review its own task. The root plan is typed by source:

- With composition enabled, the required total is the **automatic quota plus every selected direct seat plus every selected nested seat**. Selected seats do not replace the automatic quota. `Auto` reserves at least one automatic seat, or enough automatic seats to reach the two-seat minimum; a fixed count is exact. The frozen total is attached to selected and automatic bindings.
- The gate fails closed with `council_source_quorum_blocked` when a required selected reviewer is missing or duplicated, or the automatic seat count does not match the frozen quota.
- A nested child occupies exactly one root seat regardless of leaf count; its 2–8 leaves are child seats, not extra root votes.
- Composition-absent M1/M2 retain their historic automatic minimum and selected-roster quorum.

Repeated provider/model identity is reduced independence to disclose, not another independent model.

| Strategy | Contract |
| --- | --- |
| S1 Parallel (default) | Dispatch enabled sources together within finite limits; every required seat must pass. |
| S2 Escalated / on-demand | Begin from enabled sources only. Below-target score, critical/high finding, missing required evidence, same-criterion conflict or user force triggers required fresh review. For N, a bot can be Always nested or expand its same seat On trigger. |
| S3 Two-phase | Phase 2 uses fresh, independent read-only challengers from the frozen enabled sources against the phase-1 findings and artifact. Both phases must pass; unavailable independent challengers cannot pass. |

S3 independence is **per challenged lens**: a challenger may have authored a different lens in phase 1, but may not challenge the lens whose phase-1 author has the same reviewer identity. A persisted native challenge receipt binds the root/task cycle, round, seat, attempt, reviewer identity, artifact token and the frozen phase-1 author-seat and finding IDs. Dispatch requires a passing phase 1 with complete source coverage, distinct challenger identities, and a phase-1 author for every challenged lens. All phase-1 authors and the challenger must share the cycle, delivery and artifact epoch. A recorded write advances the epoch and blocks phase 2; dispatching another seat or changing round/settlement scheduling does not.

The artifact token is `<council_since>:<artifact_epoch>:<created_at>:<worker_id>`. `artifact_epoch` is the newest recorded changed-file timestamp in the Council cycle (`changed_at`), refreshed on save. It is an identity/correlation token, not a content checksum and not a scheduling counter. Same-artifact comparison ignores the seat suffix and compares the cycle and epoch.

The criteria source is a third independent choice: Architect-defined, User-defined or Hybrid. User criteria remain immutable required anchors; Hybrid may add only nonduplicative Architect lenses with provenance. Required criterion evidence and score are checked individually, and a per-criterion target cannot lower a stricter gate. The gate uses the minimum passing seat/criterion, not an average or vote. A child’s composite is the minimum eligible fresh child score; missing or unverifiable child evidence has no pass-equivalent score.

### Child lifecycle and evidence boundary

One task/delivery and artifact token → root Architect/Council freezes its config and reviewer bindings → each N seat owns a separate child Architect/Council session → the child dispatches 2–8 independent read-only leaf reviewers → native code validates child scores, required evidence, policy and artifact token → a typed child receipt settles exactly one parent seat → the root decides only after every required seat settles → one terminal task/delivery result and any separately authorized follow-up.

Child start, worker-turn end, prompt claims or partial scores do not settle the parent. Child bindings retain root cycle, parent seat, child cycle, artifact token and policy provenance. The hierarchy limit is two levels total (root plus child); nested leaves cannot create grandchildren. Child work is not the selected bot’s open chat and cannot alter the bot profile, credentials, memories or unrelated tasks. Reviewers are native read-only by default. A narrowly scoped file action requires the user’s explicit task-bound grant; shell, checkout writes and broader tools are not implied.

Verified nested leaf scores are projected read-only into `ArchitectReadSnapshot` (`councilChildLeafScores`) only for a current child receipt. Each `leafScoreRefs` entry must resolve to a child worker with the same `id:attempt`, a completed status, a seat in the receipt’s round, a valid frozen binding and matching issued authority; the criterion outcomes must match the same child cycle, parent seat, leaf attempt, round and receipt artifact token. Foreign, stale, duplicate or reference-mismatched rows make that receipt contribute no score rows. The shared presenter additionally requires the current root cycle, parent seat, child cycle, artifact token and receipt ref, withholds scores for non-pass receipts, and renders numeric scores plus criterion outcomes in the Workers inspector and the Shared Channel report. This is a read-only projection, not new quorum or a second review state store.

The Shared Channel plan uses maxDepth 2, maxRootSeats 8, at most 64 concurrent leaves, at most 128 leaf reviews per round, a 24-hour timeout and a 1,000,000-micro estimated-cost cap. A cost cap is not satisfied by unknown cost. Findings, dispositions, child/review receipts, leaf scores and usage are projected for the current root cycle only; stale cycle or artifact evidence cannot satisfy a new review. Unknown and estimated usage remains labelled as such.

### Recovery, migration and rollback

- Migration is additive. Composition is optional, schema version 1; absence preserves the legacy M1/M2 configuration path. The native test `legacy_m1_and_m2_json_keep_the_original_defaults_and_serialization` covers that Council serialization compatibility; it does not prove every historical task migration.
- The PR #152 diff also contains one additive storage migration, schema 43 → 44, adding `sa_tickets.original_admission_assignment_id` for SuperAgent task-client replay binding. It is not a Council composition table or column. The observed compatibility is Council JSON plus that additive SuperAgent column, not evidence of a database downgrade or every historical task migration.
- Native recovery links each child to its root and supports root-owned pause, resume and cancel with idempotent cleanup. Tests include `nested_child_tracks_root_pause_resume_and_cancel_with_idempotent_recovery`, `nested_escalation_decision_recovers_same_seat_phase_trigger_and_child_link` and `failed_nested_child_restart_preserves_one_link_and_terminal_reason`. They do not cover every restart, deletion, provider-loss, callback-pending and rollback state in AC-23/24.
- Safe rollback guidance, inferred from the optional config, root-owned child lifecycle and additive column: stop admitting new composed tasks; pause or settle/cancel active children through their root; preserve child links, receipts and the schema-44 data until terminal work/callbacks settle; then omit composition for new tasks to return to M1/M2. Do not drop or rewrite active child records, and do not downgrade the database. This sequence was not tested as a deployment rollback.
