## S1 model and contract decisions frozen before code

The native S1 MVP must model a **manual, explicit user request**, not generated work:

1. `orchestration`: stable ID/name, selected coordinator/worker **existing bot IDs**, project/repository scope, `policy_revision`, `enabled`, autonomy `Off`, bounded max concurrency, creation/update timestamps.
2. `ticket`: independent unique ID and immutable original objective, origin/actor and explicit-versus-inferred marker; state and optimistic `revision`, required evidence, artifact fingerprint, current assignment and checkpoint; **no FK cascade to bot/session**.
3. `mandate`: immutable snapshot of named actor, grant scope/version, allowed tools, side effects and expiry; native revocation/expiry is checked at admission and completion; a model result can never widen it. Automatic/external writes denied by default.
4. `assignment`: unique attempt ID/worker bot snapshot/session, provider/model/mode/tool policy, lease, worktree/resource identifier, start/end/result evidence, attempt/retry. Only one active per bot slot and protected resource within configured caps, even for distinct bot sessions.
5. Guarded lifecycle: `queued → running → (waiting_approval | waiting_review | blocked) → completed`, with distinct `failed`, `stopped`, `interrupted`, `inconclusive`. Explicitly reject terminal resurrection, late callbacks, stopped-task writes and mismatched revision/cycle; never finalize from a model turn alone.
6. Admission order: verify authenticated local caller, `feature.enabled`, explicit mandate, selected bot exists/unpaused, project equality, tool enforcement support, routing/hop/cycle and budget, then **durable per-bot/resource lease** before launching via existing gateway. If lease is unavailable, queue without stealing the bot's desktop/other channel conversation.
7. The native `gateway::run_finished` and other external notifications must be gate-aware **only for correlated SuperAgent sessions**; other bot sessions, direct/channel conversations, schedule, and plain Architect remain unchanged.
8. Council remains **Off** for S1. If a later task is explicitly `required` but the native Council adapter is unavailable, retain `waiting_review` or `blocked`; never silently complete.
9. `restart`: retain ticket and mandate when sessions/bots disappear, release or reconcile orphaned leases conservatively, and retain result/action receipt history. No silent duplicate dispatch or external side effects.

**Prohibited S1 shortcuts:** free-form prompt-only coordinator, reusing a normal user/desktop thread as durable Ticket identity, bypassing native tool enforcement, converting bot `full` permission to unrestricted coordinator rights, claiming per-bot serialization from the per-session gateway, or using a mock-only frontend as completion evidence.
