## Frozen S1 safety model

1. A Demand/Ticket is canonical native history, independent of bot and session rows. It keeps an immutable objective, source, actor, Team-version snapshot, mandate, revision, state, work-item graph, checkpoints and effect receipts.
2. A Run/Assignment is one attempt with an immutable role, existing bot ID, effective provider/model/mode/Skills snapshot, session, checkout/resource lease, budget and correlated result. A model turn alone is not terminal success.
3. A Mandate is user/source authority frozen at admission. It cannot be widened by model output. Side effects are denied until a separate exact-effect grant is issued and checked at dispatch and settlement.
4. All state transitions are native, revision-checked, replay-safe and audited. Stop, revoke, expiry, restart, stale callbacks and mismatched identity deny future writes/effects.
5. Read-only is the default. A write grant names exact normalized paths, Ticket, assignment, session, revision, project root and actor. Unsupported platforms fail closed. Concurrent work uses isolated worktrees or non-overlapping resource leases; never run multiple writers against the same checkout merely because the UI permits it.
6. The coordinator proposes a bounded plan and work graph; native admission chooses only configured roles and enforces caps. Workers may delegate only under explicit depth/count/concurrency/budget policy. Child work is evidence attached to its parent assignment, never a Ticket-finalization path.
7. Council-off manual acceptance remains available where the mandate permits it. Council-required work can complete only through a fresh, exact task/artifact/policy-bound native verdict or an explicitly attributed and reasoned human exception.
8. GitHub sources default Off. Off makes no source network request; Observe records filtered metadata without launching work; Auto is unavailable until trusted intake, unified admission, S1 grants, S5 recovery/effects and cancellation gates pass. Event text remains untrusted input and cannot change policy.
9. Stop/restart never replay an uncertain external effect blindly. Reconciliation requires authoritative remote identity/read-back; otherwise state remains uncertain and asks for user action.
10. UI reports configured roles, actual runs, truthful state, actual/estimated/unpriced/unknown usage and hard limits. No fabricated graph, percentage, pass, token or cost.

## Migration and rollback contract

- Add schema through forward-only, idempotent SQLite migrations. Preserve existing one-worker configurations and map them as a single-worker Team version. Keep all Ticket, Assignment, review, child and effect history independent from bot/session cascades.
- Snapshot a Team's complete effective roles, bot profile versions, Skills/harness, policy, budgets, concurrency, review policy and source route at Demand admission. Editing a Team creates a new version for future Demands; existing Runs never silently adopt it.
- Add portable manifest v2 with dependency preflight and transactional Team creation. Import starts disabled. Continue accepting v1 as the legacy two-role mapping.
- Rollback disables Auto and new admission, revokes live grants, stops sessions and retains the audit/effect ledger. Do not delete history or restore a configuration-only backup over active Ticket/effect state. A data restore requires a new explicit preview and confirmation.
