## Overview

This candidate integrates PandaCode's source and user-facing capabilities through upstream **0.3.85** while adding Extended-specific default-off controls for background updates, remote connectivity, credential forwarding, cloud management and external MCP exposure. The import is broad; it is **not** a selective port of individual features. The bullets below are a curated, evidence-linked description of the upstream release notes and Extended changes; they are **not** a claim that every previous Extended customization survived the source replacement.

## Extended SQLite upgrade compatibility

Extended schema migration **37** reconciles the upstream 0.3.85 import with databases previously written by Extended 0.6.x (schema 32). The two lineages reused migration numbers 27–32 for different changes; a legacy database could therefore lack `sessions.cloud`, `sessions.remote_backfill_base`, bot capabilities or new bot tables. The guarded reconciliation preserves existing task and bot data instead of rebuilding tables. See [EXT-070-KI-07](../../docs/extended/0.7.0/known-issues.md#ext-070-ki-07--legacy-extended-sqlite-schema-collision).

This remains an **unreleased source fix**; native upgrade smoke tests and a database backup are still required before release.

## Product features from upstream 0.3.51–0.3.85

- **More useful sidebar and task states:** compact, searchable, sortable task lists, keyboard navigation, pinned/active/finished/settled sections, task context menus and visibility for tasks that need attention ([0.3.55](../../releases/0.3.55.md), [0.3.66](../../releases/0.3.66.md), [0.3.73](../../releases/0.3.73.md)).

- **Readable execution traces and tool cards:** contextual rendering for PandaCode's tools, external MCP results, subagents and failures; completed activity folds instead of reopening unexpectedly ([0.3.52](../../releases/0.3.52.md), [0.3.74](../../releases/0.3.74.md)).
- **Visual progress snapshots:** annotated screenshots or SVG iteration previews for eligible UI tasks, with a picture-in-picture history and per-task retention limits ([0.3.78](../../releases/0.3.78.md)).
- **Responsiveness and accessibility:** consistent thread text sizing, reduced-motion-aware transitions, more efficient streaming, bounded memory retention, background diff highlighting and virtualized large diffs ([0.3.51](../../releases/0.3.51.md), [0.3.69](../../releases/0.3.69.md), [0.3.75](../../releases/0.3.75.md), [0.3.76](../../releases/0.3.76.md), [0.3.77](../../releases/0.3.77.md), [0.3.81](../../releases/0.3.81.md)).

### Agents, teams, bots and automation

- **Richer bot workspace:** bot status indicators, configurable profiles, messaging channels, shared multi-bot discussions, bot-to-bot handoffs, queued-message controls and fallback models ([0.3.57](../../releases/0.3.57.md)).
- **Panda Router model assignment:** locally computed worker-model selection, selectable team profiles, routing/escalation based on predicted success, per-harness availability, provider failover, user-assigned S–D model tiers and shorter team-model lists ([0.3.58](../../releases/0.3.58.md), [0.3.59](../../releases/0.3.59.md), [0.3.65](../../releases/0.3.65.md), [0.3.68](../../releases/0.3.68.md), [0.3.71](../../releases/0.3.71.md), [0.3.72](../../releases/0.3.72.md)).

- **Scheduled agent work:** one-time/repeating wake-ups, timed inter-thread messages, a schedules panel and bounded multi-thread workflows; existing user-approval and ownership rules apply ([0.3.80](../../releases/0.3.80.md)).
- **Additional agent integrations:** ZCode and Hermes harness support, configurable provider environment variables, thinking panels, measured token usage and related model/effort improvements ([0.3.67](../../releases/0.3.67.md)).
- **Agent telemetry preference:** optional vendor-specific telemetry opt-outs, with documented limits for providers that do not expose a verified runtime switch ([0.3.83](../../releases/0.3.83.md)).

### Machines, remote access and deployment

- **Connect transport improvements:** compressed and paginated remote histories, faster reconnects, independent worktrees when the remote project is busy, and visibility into remote subagents and team workers ([0.3.53](../../releases/0.3.53.md), [0.3.56](../../releases/0.3.56.md)).
- **Multi-machine agent orchestration:** when explicitly enabled and linked, agents can coordinate work on another PandaCode computer, subject to that device's access grants ([0.3.82](../../releases/0.3.82.md)).
- **Cloud and headless execution:** headless `pandacode serve`, cloud-agent containers/SSH options and Netlify deployment support as described by the imported upstream release ([0.3.67](../../releases/0.3.67.md)).
- **VM and cloud tools:** agent-facing machine inspection/management and cloud deployment commands exist in the imported application; the Extended controls below restrict agent-initiated mutations by default ([VM tools](../../src-tauri/src/vm/tools.rs), [deployment tools](../../src-tauri/src/cloud/deploy.rs)).

## Extended-specific settings and safety defaults

The following changes are introduced on the Extended integration branch; they do **not** come from the corresponding upstream release notes.

| Setting | Initial state | Behavior |
| --- | --- | --- |
| **Settings → About & updates → App updates** | **Off** for new/unset preferences | Background app update checks/installations are not enabled automatically. Existing explicit choices and manual checks are preserved. |
| **Settings → Remote access → Enable PandaCode Connect** | **Off** | Relay sessions and direct peer access stay disabled until the user opts in; remote hosting remains a separate choice. Explicit headless serving retains its intended behavior. |
| **Settings → Feature controls → Check agent updates automatically** | **Off** | No periodic agent-version checks; manual **Check updates** remains available. |
| **Transfer local credentials to cloud agents** | **Off** | New credential-copy steps are rejected. Does **not** revoke previously copied secrets; see [KI-03](../../docs/extended/0.7.0/known-issues.md#ext-070-ki-03--credentials-already-sent-to-cloud-machines-are-not-revoked). |
| **Allow agent VM and cloud management** | **Off** | Agent-facing VM mutations and deployment commands are blocked. Read-only inventory and manual machine management remain available. |
| **Allow external MCP servers in Claude and Codex** | **Off** | Intended to isolate external MCPs for newly launched Claude/Codex processes while preserving local PandaCode tools. **The Codex behavior is not yet verified; see KI-01.** Other harnesses use their own MCP policies. |
| **Pause all bots and external channels** | **Off** (bots remain active) | Enabling the pause stops bot work and gates new bot messages and schedules; existing per-bot preferences are preserved. |
| **Use direct LAN / Tailscale routes** | **On**, only when Connect is enabled | Prefer authenticated direct routes when Connect is opted into; the user can disable direct routes independently. |

Preferences are persisted in native storage and normally reload on application restart. A failed or unreadable preference store is **not** equivalent to a validated saved setting; see [KI-04](../../docs/extended/0.7.0/known-issues.md#ext-070-ki-04--failed-settings-reads-can-reactivate-bots-or-lan-routes).

Implementation references: [Feature controls](../../src-tauri/src/feature_controls.rs), [Settings UI](../../src/feature-controls.ts), [Connect routes](../../src-tauri/src/remote/routes.rs) and [Settings guide](../../docs/extended/0.7.0/feature-controls.md).

## Upgrade and operator notes

1. **Not published:** the planned Extended version is `0.7.0`, but the imported project metadata still reports upstream `0.3.85`. Do not create a `v0.7.0` release or installer until the version files, release workflow, asset branding and Extended provenance are reconciled.
2. **Check feature opt-ins after upgrading:** application and Connect auto-start defaults have changed. Enable only the capabilities you need in Settings. An existing explicit choice may be retained.
3. **Cloud agent starts:** when local credential transfer is disabled, the current cloud flow can still prepare a machine before rejecting credential sync. Review costs and the [known issue](../../docs/extended/0.7.0/known-issues.md#ext-070-ki-02--cloud-machines-may-be-provisioned-before-the-credential-gate).
4. **Running agents:** changing an external MCP preference does not immediately reconfigure or revoke capabilities in an already running agent; restart affected tasks if an immediate policy change is needed.
5. **History/parity:** the broad upstream source replacement removed some Extended-only release/documentation files present on `main` (including the prior `releases/extended/0.6.0.md` in this branch). Review which history and Extended-only behaviors must be restored **before merging**. This note does not assert successful Extended parity.

## Known issues and deferred work

The maintainable issue register is [**Extended 0.7.0 Known Issues**](../../docs/extended/0.7.0/known-issues.md). Its five **open application-level entries** cover:

- **KI-01:** Codex external-MCP isolation may not be effective when set to Off.
- **KI-02:** Cloud machine provisioning may precede the credential-transfer gate.
- **KI-03:** Disabling credential transfer does not revoke credentials already copied to cloud machines.
- **KI-04:** An unreadable settings store can silently fall back to bot-active and direct-LAN-enabled defaults.
- **KI-05:** Already running agents can retain launch-time MCP access after the flag is switched Off.

These are recorded as **open, deferred findings**, not accepted risks or resolved vulnerabilities. Prioritize and confirm fixes separately before claiming the associated security guarantees.

The separate [KI-06 dependency finding](../../docs/extended/0.7.0/known-issues.md#ext-070-ki-06--mobile-expo-dependency-audit-remediated-in-source) is tracked as resolved in this source candidate; see the verification record below.

## Dependency security remediation (Extended-owned)

The Extended integration remediates known npm vulnerabilities across desktop, website and mobile, with relay independently audited. The dependency patches and immutable build evidence are maintained in [Extended 0.7.0 Dependency Security](../../docs/extended/0.7.0/dependency-security.md).

- **Desktop:** `dompurify` 3.4.17, `katex` 0.18.2, `vite` 7.3.7 and `source-map-js` 1.2.2.
- **Website:** `vite` 8.3.3, `source-map-js` 1.2.2, `devalue` 5.9.3, `sharp` 0.35.5 and aligned platform bindings/libvips, `smol-toml` 1.9.0, `undici` 8.12.2, `zod` 4.6.6.
- **Mobile (Expo 58 retained):** `glob` 14.0.3, `minimatch` 11.0.3, `node-forge` 1.4.2, `zod` 4.6.7, plus dependent updates. No unsupported Expo 51 downgrade.
- **deepmerge:** there is **no upstream fixed release** for the observed prototype poisoning. The vulnerability was independently reproduced after a superficially clean npm audit and fixed by a MIT-licensed [Extended-local vendored copy](../../mobile/vendor/extended/deepmerge/README.md) with source/target pollution regression checks.
- **Prevention:** required GitHub Actions audits all four npm lockfiles; the mobile pipeline runs frozen install, typecheck, unit tests, Expo config, lint and iOS JS export.

The [dependency known issue KI-06](../../docs/extended/0.7.0/known-issues.md#ext-070-ki-06--mobile-expo-dependency-audit-remediated-in-source) is **resolved in the source candidate** once the corresponding security regression/audit evidence is confirmed. Five **non-dependency** application issues remain open, as recorded separately. Audit success does not certify native installers, the Rust supply chain or all possible zero-day risks.
