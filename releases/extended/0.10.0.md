### Security and compatibility

- `zip` 9.0.5 is the first patched release for the reported ZIP dual-header parser discrepancy. Rust 1.88 MSRV, `deflate` features and normal dependency requirements remain unchanged versus 9.0.4; no unrelated dependency upgrade or product-flow change is intended.
- The observed VSIX importer reads archives using `ZipArchive`/`by_name`; an application-level exploitation path has **not** been demonstrated. See the [dependency-security record](../../docs/extended/0.10.0/dependency-security.md) for source references, exact lock checksum and required Rust/CI verification.
- Preserve and revalidate all existing Extended remediations and migration paths, including the mobile `deepmerge` security fork.

## Upgrade considerations and known limitations

- **Existing installations:** a green CI run is not proof that an existing installation or SQLite database upgrades safely. Test representative persisted data and back up before a migration exercise. Do not advertise binary upgrade safety without that evidence.
- **Functional parity:** the previous source comparison reported **65 divergent shared paths** at pinned upstream 0.3.97; that is historical evidence requiring per-hunk reconciliation and a new full inventory at the actual 0.10.0 final SHA, not proof of a regression or of full behavioral parity.
- **Native and remote behavior:** actual installed Windows/macOS/Linux runs, two-device Connect, Settings On/Off and restart, bots, MCP, cloud/VM operations, credential transfer and mobile scenarios remain to be accepted for the final candidate.
- **Distribution identity blocker:** the existing `.github/workflows/release.yml` reads the Tauri application's source version and notes at `releases/{source_version}.md`. Tagging `v0.10.0` while the application manifests declare upstream 0.3.97 will fail that workflow's version check. Resolve independent Extended distribution packaging/version identity before using this workflow for 0.10.0 installers. Do **not** rewrite upstream application manifests or weaken the version-parity test to make a tag pass.
- See [0.10.0 known issues](../../docs/extended/0.10.0/known-issues.md) and [readiness checklist](../../docs/extended/0.10.0/release-checklist.md). Evidence gaps are not automatically confirmed bugs.
