## What is new in 0.11.0?

### Inherited from PandaCode 0.3.100 (not Extended-exclusive)

- **Claude Code/Codex account pools:** multiple owned subscription logins can be assigned to a provider pool; a usage-limit stop can move the same run to a ready account, with visible account status, hold persistence, and queued-input preservation. Near-limit handling can select an alternative between turns.
- **One-click account sign-in:** uses the provider CLI login and browser flow with a private per-account config folder; a code entry path and a copyable CLI command remain available.
- **UI and tests:** provider connections panel, live-preview controls and account-pool browser/Rust tests were imported with the implementation.

Source: [fork commit `e0b65e51`](https://github.com/ginmp8/pandacode/commit/e0b65e51c4b6bc9c67982eaed08f7f13985fa01a), [original upstream release notes](../0.3.100.md). Integrated in [Extended commit `a28ce807`](https://github.com/ginmp8/pandacode-extended/commit/a28ce807a9bcc3a8583440ff6035deb1fd0854da); **7 new + 18 modified upstream paths**. Source limitations remain: pool accounts must be owned subscription logins, cloud runs/goal operations are not pooled, live two-account Codex and complete real sign-in coverage are incomplete. The Extended integration has **not** independently established native end-to-end behavior.

No new Extended-exclusive feature or vulnerability remediation is claimed by this upstream import. Previously implemented controls and the Rust ZIP 9.0.5 remediation are preserved.
