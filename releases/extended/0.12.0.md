## Compatibility and release constraints

- Continue the [full upstream functional parity contract](../../docs/extended/upstream/parity-contract.md) while retaining Extended-only controls and security/dependency remediations.
- Never remove or stub upstream capabilities due solely to a perceived risk; optional controls govern operations without deleting their implementations.
- Keep upstream app versions in npm, Cargo, Tauri and lockfiles aligned to the fork. **Do not rewrite them as 0.12.0.**
- Preserve original upstream `releases/*.md` files and keep Extended notes under `releases/extended/`.
- Only update `base/development` during source synchronization. Promote to `base/hardened`, and later to `main`, with **rebase-only** PR integrations; do not merge or rebase `main` into `base/hardened`.
- No automatic npm publication. An Extended `v0.12.0` tag and GitHub Release require separately authorized actions after acceptance.
