# PandaCode Extended 0.5.0

PandaCode Extended **0.5.0** integrates changes from the original PandaCode **0.3.42 through 0.3.47** range and restores missing compatible features found in the **0.3.28 through 0.3.42** historical review. The full display identity remains **0.5.0+pc.0.3.47**. Existing Extended features and reviewed security controls remain part of the application.

This is the requested source candidate for [issue #22](https://github.com/ginmp8/pandacode-extended/issues/22) and [issue #24](https://github.com/ginmp8/pandacode-extended/issues/24). See the [integration map](../../docs/upstream-integration-0.5.0.md) and [historical feature map](../../docs/upstream-parity-0.3.28-0.3.42.md) for source identities, implementation paths, included/excluded features, code examples and verification limits.

## New and improved

### Historical feature coverage

- Kilo Code is integrated with ACP, provider/model menus, connections, Skills, console and remote host support. Devin and the existing harnesses remain available. Unsupported console permission modes are refused explicitly.
- Cline can use the installed CLI console and read-only capability discovery. Claude-family **Approve for me** is an explicit choice with native, mobile, team and remote authorization checks; existing defaults are unchanged.
- Jev supports explicit OpenRouter provider/model selection, an on-demand bounded catalog and protected-store credentials. Existing TypeSafe settings remain the default.
- Bot profiles support personality text, explicit MCP selections and eligible project-task binding. Scoped, hash-pinned Skills remain authoritative. Web chat renders validated bot icons, and delayed settings responses cannot change another bot's save target.
- File tabs preserve each task's Conversation and workspace ownership. Local PDF, Word, spreadsheet and image viewers use bounded reads, archive/image limits and sanitized rendering. Unsupported drops insert quoted path/name text without submitting or leaking into another task's draft.
- Eleven additional cloud providers support explicit manual sandbox management with accurate lifecycle/image/lease capabilities. Automatic cloud-agent runtime, credential and checkout transport remains excluded. See the [provider matrix](../../docs/cloud-sandboxes.md).
- Compact mobile Inbox supports search plus computer/project filters. Relay sign-in has a global limiter and deployment configuration guard, with cheap rejection of oversized throttled frames.
- Provider settings layout, single-instance window focus, AppImage `GDK_BACKEND` handling and an explicit Linux system-browser action are restored while keeping Browser QA and origin restrictions.
- Invalid stored Connect keys fail without replacement. Protected secret storage, pinned device trust, replay controls and independent remote privilege grants remain in force.
- The local SBOM helper inventories current Extended installer names and isolated lockfiles with existing offline scanners. It never downloads tools/databases or publishes artifacts, and incomplete results remain explicit.

### Devin CLI

- Choose an installed Devin CLI from the harness picker and use its existing sign-in.
- Discover its model catalog and each model's supported reasoning levels. Text-only models reject image prompts before sending; Fusion models do not receive an invented effort slider.
- Use Devin's Code, Plan and explicit Bypass modes through the existing permission controls. One-time approvals and plan implementation do not silently authorize permanent bypass.
- Continue matching sessions, steer supported running turns, open the session in the task console and discover supported slash commands. Empty discovery sessions are cleaned up.

### Sidebar and inspector

- Active, Needs review and Completed sections make running work, unseen completed turns and finished tasks visible in the sidebar. Completed starts collapsed and remembers its state.
- Complete/reopen, archive/restore and delete actions operate on the row's task.
- The inspector uses persistent, closable tabs. Changes is initially open; the add menu opens Files, Search, Browser, Pull request, Simulators, VMs and Design.
- Changes displays file diffs together, with scope/totals, per-file actions and staging/commit/worktree controls. Diff content refreshes while an agent edits files.
- The narrow-thread worker-label fix remains in place, together with Extended's chat/sidebar stability behavior.

### Remote tasks and mobile Connect

- Remote follow-ups reach the computer that owns the task, including tasks created while automatic Team mode is enabled. Local Team controls are not offered on mirrors.
- A first prompt appears immediately while the host finds the project, downloads the repository, prepares the checkout and starts the agent. Failures retain the draft and offer Retry/Dismiss.
- Images and screenshots travel in bounded encrypted chunks: at most four PNG/JPEG/WebP images per prompt, each at most 5 MiB. The receiver uses its own capture names and verifies upload ownership.
- Final synchronization keeps remote prompts and streamed replies visible.
- Mobile Connect can display team worker state/transcripts, team messages, linked pull requests, file changes, bots, message images, project icons, sub-agent summaries and last activity.
- Team tasks remain Running while workers are active; Stop pauses the team.
- Threads load newest-first. The host supports bounded concurrent reads and read batches while retaining ordered mutations, bounded results and short-lived pull-request caches.

## Extended features preserved

- Review & coordination, manual Advisor/Committee profiles, Team inspector, Attention and explicit Handoff.
- Browser QA, bounded scenarios, explicit evidence and workflow templates.
- GitHub issue drafts, Board stage controls and linked-issue close/reopen confirmations.
- Connection isolation, bounded context recovery, commit/hash-pinned Skills, Edit/Rewind and validated historical attachment controls.
- Per-device Connect trust, independent remote Full access, persistent replay protection, OS credential storage, scriptless file previews and explicit bot-notification approval.
- Disabled automatic app/agent updates, network installers and unattended publication.

## Version, history and migration

The technical version is `0.5.0` in npm, Cargo and Tauri. The `+pc.0.3.47` suffix is display metadata only. Native bundle names use `PandaCode Extended`; package/CLI/tool identifiers, bundle ID `ai.pandacode.desktop`, existing credential paths and app-data paths remain unchanged. Extended and original PandaCode therefore still share an application identity and are not independent side-by-side installations.

The published `0.4.0` release and note remain unchanged. Original PandaCode notes stay under `releases/`; Extended notes remain under `releases/extended/`. Historical security evidence remains immutable. Source ancestry still records `0.3.28`. The historical supplement records 14 published release feature sections and one source-only note, with source digests. Intentional security exclusions remain, so this candidate does not claim a complete source rebase or unrestricted upstream parity.

Database migration **28** adds durable attachment metadata and preserves Extended's existing migration **27** for GitHub issue actions. Migration **29** adds bot profile/project-task bindings after both of those migrations. Desktop and mobile manifests share the technical version; the release-version command and validation gate keep them synchronized. Mobile has its own new Extended application identifiers and no automatic update or publication configuration.

Back up application data before replacing an installation. Remote/mobile participants must use compatible Extended protocol behavior and retain explicit device trust. An original upstream installer or the public `npx pandacode` package does not install this candidate's protections.

## Validation limits and distribution

The [parent verification report](../../docs/verification-0.5.0.md) and [historical integration report](../../docs/verification-historical-0.5.0.md) record the executed build, regression, browser, native, mobile and relay results and their limits. Upstream validation statements do not certify Extended. Live provider/cloud accounts, real remote devices, mobile packaging, platform credential stores and native installers need their own environment-specific verification.

This source change does not publish `v0.5.0`, signed installers, an updater feed or an npm package. Use the reviewed [local packaging procedure](../../docs/releasing.md) after validation and an explicit publication decision.
