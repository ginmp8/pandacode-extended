# PandaCode Extended 0.6.0 — Source candidate

**Technical version:** `0.6.0`  
**Reference label:** `0.6.0+pc.0.3.50`  
**Upstream releases:** [0.3.49](https://github.com/aicodeking/pandacode/releases/tag/v0.3.49) and [0.3.50](https://github.com/aicodeking/pandacode/releases/tag/v0.3.50)

## Upstream functionality brought into the candidate

- **Connect 0.3.49:** remote LAN/Tailscale route negotiation and relay fallback; host-side device approval, scoped View/Control/Full grants, timed pairing code, diagnostics and reconnect controls; replay/paging and start/stop recovery. Integration paths are in issue #38 and `docs/upstream-integration-0.6.0.md`.
- **Agent traces 0.3.50:** an inline trace rail, latest-result cards, result details for shell/diff/files/web/MCP/teams/skills, inline local brand marks and source citations, smooth link/code streaming and reduced-motion-aware trace presentation. Integration paths are in issue #39.
- **Extended compatibility:** existing GitHub task/Board flows, bot/chat features and independent source and distribution identity are intentionally retained.

## Security policy and deliberate exclusions

The source port is subject to Extended's existing durable anti-replay checks, key revocation and trust pinning, separate default-off remote Full-access grant, disabled automatic updaters and online bootstrap, safe preview sandboxing and consent boundaries. In particular, upstream's known direct-route probing behavior for non-approved peers is **not allowed** in Extended. Untrusted announced private addresses must never be probed automatically.

## Validation and limits

This is an **unpublished integration candidate**, not a verified native installer or a guarantee of feature parity. The native Rust refactor, source-version validator and relevant Playwright, mobile and security regressions must all pass; two physical computers and platform-specific behavior remain unverified until expressly tested. GitHub PR #40 is ready for review, unmerged. Its expanded CI and independent two-device acceptance remain mandatory before merging. No merge, release, tag, auto-update or deployment has occurred.

See [issue #38](https://github.com/ginmp8/pandacode-extended/issues/38), [issue #39](https://github.com/ginmp8/pandacode-extended/issues/39), and [integration evidence](../../docs/upstream-integration-0.6.0.md).

## Follow-up security and UX acceptance

- Tracked in #41: bot scheduling permission ceilings, fingerprint-bound approval, explicit revocation and non-resurrection of scoped grants.
- Connect settings now expose scoped device decisions, pairing codes and an opt-in for private-address direct routes; these require live verification.
- Diagnostics must redact private network addresses from the IPC snapshot as well as exported reports.
- Previously omitted pairing, diagnostics, Markdown and agent-trace browser suites are added to the required CI selection.
- Linux CI is not a substitute for a physical two-device or macOS/Windows transport test. These capabilities are not certified in this source candidate.

## Independent audit corrections

Issue #42 and the follow-up challenge pass strengthen effective method authorization, fenced pairing and revocation, complete fingerprint display, and private-path diagnostic redaction. Schema 32 separates schedule authorization from retained activity and atomically accepts each occurrence with its initiating message. Busy or failed admission does not consume a once schedule. Trace fixes bound untrusted search highlighting, retain manual raw disclosure and reader selection, and settle active motion when reduced motion changes.

The [correction record](../../docs/pr40-audit-corrections.md) maps findings to source paths and regression scenarios, including previously omitted browser and mobile coverage. Ready for review follows the owner's instruction; it does not waive the remaining acceptance gates above. The version remains 0.6.0.
